# Manual Forensic Investigation: Identifying Hidden Artifacts in FAT32 (HxD)

## 1. Methodology
To locate hidden files or directories within this FAT32 image, I analyzed the **Short File Name (SFN)** entries located in the Root Directory. My primary focus was on the **File Attributes** byte, located at the 12th byte (Offset `0x0B`) of the 32-byte SFN entry. 

* **Indicator:** If this byte is set to **`0x02`**, the file or directory is flagged as "Hidden" by the filesystem.

---

## 2. Root Directory Analysis
I loaded the target image, `FAT32_HIDDEN.001`, into HxD and navigated to the Root Directory offset at **`0x400000`** (calculated via the Boot Sector). 

Before scanning for individual files, I checked for fragmentation within the directory itself. I observed that the root directory entries were split across multiple clusters, specifically starting at offsets **`00400200`** and **`00400600`**. This fragmentation is common in Windows for efficiency but requires checking multiple locations to ensure no evidence is missed.

### A. Discovery of Hidden Directory: "M@LL0V3"
At the initial Root Directory offset (`00400000`), I identified a suspicious Long File Name (LFN) entry linked to a Short File Name (SFN) entry at offset **`004000A0`**.

I performed a hex breakdown of the SFN entry to determine its properties:

* **File Name:** `M@LL0V3` (Hex: `4D 40 4C 4C 30 56 33 20`).
* **Attributes:** `0x13`. This is a combination of **Read-only (`0x01`)**, **Hidden (`0x02`)**, and **Directory (`0x10`)**.
* **Creation Date:** Friday, December 20th, 2024.
* **First Cluster:** `05 00` (Cluster 5).
* **File Size:** `00` (Indicates a directory).

**Conclusion:** I successfully identified a hidden, read-only directory named **`M@LL0V3`**.

---

## 3. File Analysis
I proceeded to the next cluster offset at **`00400200`**. Here, I observed standard Windows system entries, including `WPSettings.dat` and dot entries (`.` and `..`). Finding no anomalies there, I moved to the next cluster offset at **`00400600`**.

### B. Discovery of Hidden File: "BeMyValent1ne.txt"
At offset **`00400600`**, I located another hidden artifact. I focused on the SFN entry starting at **`00400680`**, which was linked to a preceding LFN entry.

* **Attributes:** `0x02`. This explicitly flags the file as **Hidden**.
* **Creation/Access Date:** Friday, December 20th, 2024.
